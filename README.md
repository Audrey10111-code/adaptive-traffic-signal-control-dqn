# Adaptive Traffic Signal Control Using DQN

This repository contains an educational Deep Q-Network (DQN) pipeline for a simplified four-way traffic intersection.

## Project mapping

- **Agent:** DQN traffic-signal controller.
- **Environment:** Synthetic queue-based four-approach intersection.
- **State:** Four queue sizes, current phase (one-hot), time in current phase, and demand period (one-hot).
- **Actions:** Keep current phase, switch to north-south, switch to east-west, or extend the current green.
- **Reward:** Negative waiting-time cost, longest-queue penalty, and phase-switch penalty.
- **Safety:** Action masking enforces minimum and maximum green rules. A switch includes a simulated 5-second all-red clearance interval before the new green phase.
- **Algorithm:** DQN with experience replay, a target network, epsilon-greedy exploration, and Huber loss.
- **Baselines:** Fixed-time and longest-queue-first.

## Run in Google Colab or locally

```bash
pip install -r requirements.txt
python dqn_traffic.py --episodes 80 --steps 240 --eval-episodes 10
```

Quick test:

```bash
python dqn_traffic.py --episodes 5 --steps 60 --eval-episodes 2
```

## Generated outputs

- `traffic_rl_outputs/training_log.csv` — episode rewards, epsilon values and training losses.
- `traffic_rl_outputs/evaluation_results.csv` — results for each test episode and controller.
- `traffic_rl_outputs/evaluation_summary.csv` — mean and standard deviation of evaluation metrics.
- `traffic_rl_outputs/training_curve.png` — training reward curve.
- `traffic_rl_outputs/dqn_traffic_model.pt` — saved neural-network weights.

## Important scope and limitations

This is a **simplified synthetic queue simulator**, not a calibrated traffic model, SUMO simulation, or deployment-ready traffic controller. Each episode contains three representative demand periods (off-peak, morning peak, evening peak); it is not a full 24-hour simulation. Arrival and service rates are illustrative and should be described as assumptions. Results must be generated by running the code and reported honestly.

The proposal mentions power interruptions. This implementation does not model a grid outage or a backup-power system. A real deployment must have an independent fail-safe signal controller; the RL agent must never be the only safety mechanism.

Before real-world use, the model would need calibrated traffic data, detailed lane/turn movements, pedestrian phases, emergency-vehicle priority, formal safety verification, and testing in a validated simulator such as SUMO.

The `results/` folder contains the evaluation summary reconstructed from the ten-episode summary values supplied by the project team, the training curve image supplied from the completed Colab run, and a waiting-time comparison chart. The full training log and per-episode evaluation results should also be downloaded from the Colab output folder and added before publishing if they are available.
